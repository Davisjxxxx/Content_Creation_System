# ComfyUI workflow integration

Avatar V2 keeps the desktop application independent from ComfyUI internals. Export the exact graph you want using **Save (API Format)** and replace only the fields the app should control with placeholders.

## Core placeholders

- `${PROMPT}`
- `${NEGATIVE_PROMPT}`
- `${INIT_IMAGE}`
- `${LAST_FRAME}`
- `${MOTION_VIDEO}`
- `${SCENE_IMAGE}`
- `${AUDIO}`
- `${WIDTH}`
- `${HEIGHT}`
- `${FPS}`
- `${FRAMES}`
- `${SEED}`
- `${STEPS}`
- `${CFG}`
- `${RUNTIME_PROFILE}`

## MiniMax H3 placeholders

H3 Ref2VA receives positional reference bindings generated by Avatar V2:

- `${H3_PICTURE_1}` ... `${H3_PICTURE_9}`
- `${H3_VIDEO_1}` ... `${H3_VIDEO_3}`
- `${H3_AUDIO_1}` ... `${H3_AUDIO_3}`
- `${H3_PICTURE_COUNT}`
- `${H3_VIDEO_COUNT}`
- `${H3_AUDIO_COUNT}`
- `${H3_DIFFUSION_MODEL}`

The desktop app discovers the diffusion models already visible to ComfyUI. Runtime profiles can then choose a compatible installed model. On consumer 12–16 GB cards, `Auto` prefers an installed pruned INT8 checkpoint. `H3 INT8 · 12 GB` forces that preference. `H3 Low Memory` also reduces the canvas and steps. No model weights are downloaded by the app.

The prompt compiler maps references explicitly as `<Picture N>`, `<Video N>`, and `<Audio N>`. The first picture is the primary identity anchor. Motion-video references are explicitly assigned motion/camera choreography rather than identity.

## H3-native constraints handled by the app

- 24 fps
- canvas dimensions snapped to the H3-supported multiple-of-32 presets
- frame count snapped to the valid `17k+5` grid
- practical single-clip duration capped at 15 seconds
- presets including `480×864` vertical and `864×480` landscape for 12 GB-class testing

## Example API-format fragment

```json
{
  "10": {
    "class_type": "UNETLoader",
    "inputs": {
      "unet_name": "${H3_DIFFUSION_MODEL}",
      "weight_dtype": "default"
    }
  },
  "20": {
    "class_type": "LoadImage",
    "inputs": {"image": "${H3_PICTURE_1}"}
  },
  "30": {
    "class_type": "KSamplerSelect",
    "inputs": {"sampler_name": "res_multistep"}
  }
}
```

The exact node names/graph should come from the version of ComfyUI you have installed. Do not blindly paste the fragment above into a workflow; use it only to understand placeholder substitution.

## Recommended exports

Keep separate tested workflow exports such as:

- `h3_ref2va_api.json`
- `h3_fl2va_api.json`
- `wan22_i2v_api.json`

The supplied workflow remains authoritative for node topology, sampler, scheduler, VAEs, encoders, LoRAs and other model-specific details. Avatar V2 controls the job values and records the exact runtime profile used.

When `ComfyUI/input` is configured, files are staged directly there. If it is not configured, Avatar V2 uses ComfyUI's HTTP upload endpoint so the desktop app can still run against another ComfyUI machine on the LAN.
